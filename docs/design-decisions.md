# 设计决策

## 不在 Trending 之后增加主题分类器

榜单已经表达社区热度，再加二分类会提前替读者丢弃信息。LLM 的职责是压缩与翻译，让读者
更快判断是否值得打开，而不是决定读者应该关注什么。

## 两个数据源不共享业务模型

GitHub 的标识是仓库全名，核心指标是 star 与周期增长；HN 的标识是 item ID，核心指标是分数
和评论。强行共享表或基类会制造大量可选字段和条件分支，因此只复用基础设施。

## HN 默认延迟抓取

HN 当天帖子的分数尚未稳定，直接抓“今天”会偏向较早发布的内容。默认 `HN_LAG_DAYS=2`，
按 UTC 切分日期，并先应用分数门槛再截取前 N 条。

## 摘要按提示词版本保存

GitHub 与 HN 使用不同提示词和版本号。同一条内容在提示词调整后可以保留新旧摘要供比较；
某条摘要失败时通知仍可使用原始描述，并在下次运行时重试。

推理模型可能把输出额度全部用于 reasoning，导致 HTTP 200 但正文为空。摘要请求从
`LLM_SUMMARY_INITIAL_TOKENS` 开始；仅在 `finish_reason=length` 时逐次翻倍，最高不超过
`LLM_SUMMARY_MAX_TOKENS`。其他空响应按原额度重采样，避免无依据地扩大消耗。

HN 外链来自任意第三方网站，正文不可用属于预期降级。成功正文缓存 30 天，失败结果只缓存
1 天，并按超时、网络、HTTP、非 HTML 和提取为空汇总，下一天可以从瞬时故障中恢复。

## 单 worker 内置调度

部署限定单副本、单 Uvicorn worker。FastAPI 启动时创建异步定时任务，到点后在线程中运行
已有同步流水线，保持网页响应；时间与时区由环境变量配置。
执行完成后计算下一次时间，不做停机补跑或整批重试，也不引入跨进程锁和专门调度状态表。
Compose 只需一个服务，挂载项目 `data/`，无需宿主 crontab 或额外调度容器。
